## C5 - The flat Predicted Time model (2026-09-29)
- Done: packages/shared/src/flat-model.ts (exported from the index): flatPredictedTime(benchmarks, metres) -> { soft: BenchmarkDistanceId[], prediction: { seconds (unrounded), confidence: 'high' | 'low' } | null }, taking BenchmarkTime[] ({ distance, seconds }, any order). Soft = pace strictly slower than some longer Benchmark's pace (equal pace isn't soft; the longest never is); soft ones are dropped, and < 2 usable (MIN_USABLE_BENCHMARKS) -> prediction null ("no prediction"). Inside the usable range: log-log interpolation between neighbours, exact at Benchmark points, high confidence. Below/above the range: the two nearest usable Benchmarks' exponent, clamped to EXTRAPOLATION_EXPONENT_MIN/MAX, from the end Benchmark, low confidence (so every Segment under 400 m is low). softBenchmarks(benchmarks) returns the same soft set alone for the Fitness Profile page (N2/U1).
- Verified: flat-model.test.ts (32 tests): exactness at all 13 Benchmark points, geometric-mean midpoint, neighbours only, monotonic 200 m-50 km, extrapolation at both ends from the nearest pair, clamping steep and shallow exponents at both ends, sub-400 m low, blank / one / two-with-one-soft -> null, soft ignored, input order, soft detection cases. `pnpm typecheck && pnpm lint && pnpm test` (shared 184, api 179, web 49) and `pnpm test:e2e` (18) pass. No UI changed.
- Notes: C6 should convert the Segment to an equivalent flat distance and call flatPredictedTime on it; its "outside the Benchmark range" low-confidence reason is prediction.confidence === 'low' here (judged on the equivalent flat distance).
